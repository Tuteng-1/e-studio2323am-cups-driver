# e-STUDIO2823AM 抓包方案（Windows 端）

目标：在实体 x64 Windows 上，用原厂 GDI 驱动生成一批**原始打印数据流**（`.prn`），
用于还原私有光栅协议。这些文件是后续写 macOS CUPS filter 的唯一事实来源。

> 注意：本机 Parallels 是 Windows 11 ARM64，无法加载 x64 打印驱动，所以这一步必须在你的实体 x64 Windows 上做。

---

## 0. 准备

1. 在 x64 Windows 上**以管理员身份**安装驱动目录里的安装程序（`Drivers/e-STUDIO2823AMSeries/` 下的 setup）。
   如果只想抓文件、不想有真机，也**必须**让驱动安装成功（端口可以指向 `FILE:` 或一个假的 `LPT1`）。
2. 安装完成后，在「设备和打印机」里确认队列名，例如 `TOSHIBA e-STUDIO2823AM`。
3. 建一个工作目录 `C:\eSTUDIO-capture\`，所有输出都放这里。
4. 关闭「双向支持 / 状态监控」对抓包的干扰（后面第 4 步单独抓一次状态查询即可）。

---

## 1. 首选抓法：驱动自带的「打印到文件」

这是**最准确**的方式，得到的字节就是 `WritePrinter` 收到的字节：

1. 打开任意文档 → 打印 → 选择该队列 → **打印机属性 / 首选项**，按下面的矩阵设置参数。
2. 在打印对话框里勾选 **「打印到文件」(Print to file)**。
3. 保存为 `C:\eSTUDIO-capture\<编号>_<描述>.prn`。
4. 记下本次用的设置（写进 `manifest.txt`，模板见第 5 节）。

如果驱动界面没有「打印到文件」，改用「端口」方式：

- 打印机属性 → 端口 → 添加端口 → 类型选 **Local Port** → 端口名填 `C:\eSTUDIO-capture\test.prn`。
- 之后每次打印前把端口名改成想要的文件名（Local Port 会直接写文件，等价于 raw 落盘）。

---

## 2. 备选抓法：FILE: 端口

打印机属性 → 端口 → 添加端口 → **Local Port** → `FILE:`。
打印时会弹出「保存到文件」对话框，输入路径即可。

⚠️ 若用 `FILE:` 抓到的数据为空或明显被截断，说明打印处理器走了别的路径，改用第 1 步的 Local Port 绝对路径方式。

---

## 3. 抓包矩阵（必须按此顺序，每项单独一个文件）

先用 **A4 / 纵向 / 600×600dpi / 单面 / 1 份 / 无省墨** 作为基线，然后每次只改一个变量。

### 3.1 基线 + 图像内容（最重要）

| 编号 | 内容 | 说明 |
|---|---|---|
| 01 | 全白 A4 | 得到"空页"骨架、页头/页尾 |
| 02 | 全黑 A4（整页填充黑色矩形） | 得到最坏压缩情况、行字节数 |
| 03 | 左上角 1 个黑点（1×1 像素） | 定位像素位序/字节序 |
| 04 | 一条水平 1px 黑线，y=0 | 定位行对齐/band 头 |
| 05 | 一条垂直 1px 黑线，x=0 | 定位列对齐 |
| 06 | 8×8 棋盘格（1px 交替） | 判断是否有 RLE/位平面 |
| 07 | 纯文字页（中文+英文混排，宋体/Arial 各一行） | 字体是否转轮廓、是否嵌字体 |
| 08 | 灰阶渐变条（0%→100%，16 级） | 判断半色调/灰度编码 |
| 09 | 50% 灰整页 | 半色调矩阵 |
| 10 | 彩色图片（若有彩色机型）/ 纯黑文字扫描件 | 判断是否 1bpp |

> 01–06 必须用**同一台机器、同一份文档模板**，只改图形内容，便于差分对比。
> 建议用画图/Photoshop 生成一个 A4@600dpi 的 PNG（4960×7016），再「打印」它，缩放选 100%。

### 3.2 分辨率

| 编号 | 设置 |
|---|---|
| 11 | 600×600 dpi |
| 12 | 1200×1200 dpi（若驱动提供） |
| 13 | 2400×600 dpi（若驱动提供） |

内容统一用「左上角黑点 + 一条 100px 横线」，方便比较行宽和头部字段。

### 3.3 纸张 / 方向

| 编号 | 设置 |
|---|---|
| 14 | A4 纵向（基线，同 01） |
| 15 | A4 横向 |
| 16 | Letter 纵向 |
| 17 | A3 纵向（若支持） |
| 18 | A5 纵向 |
| 19 | 自定义纸张 100×150mm（若支持） |

### 3.4 多页 / 多份 / 进纸盒

| 编号 | 设置 |
|---|---|
| 20 | 2 页文档（原本想抓双面，但本机无自动双面单元，最终 `DUPLEX=OFF`） |
| 21 | 单面，2 页文档（和 20 对比页边界） |
| 22 | 份数 = 3，1 页文档（看驱动是否重复发页还是只发一次+份数字段） |
| 23 | 纸盒 1 / 24 纸盒 2 / 25 手送（若有多纸盒） |

### 3.5 驱动选项（影响编码的）

| 编号 | 设置 |
|---|---|
| 26 | 省墨模式 开 |
| 27 | 图像质量/分辨率优先 vs 速度优先 |
| 28 | 缩放 50% |
| 29 | 每张 2 页（N-up 2in1） |
| 30 | 水印 开（文字水印） |

### 3.6 状态/控制通道（可选但有用）

| 编号 | 说明 |
|---|---|
| 31 | 在 Windows 上点「打印机状态/墨粉余量」，同时用 Wireshark 抓 9100/SNMP 流量（看状态查询用的 PJL/SNMP OID） |

## 4. 附带材料（同样重要）

放在同目录：

- `manifest.txt`：每个 `.prn` 的编号、设置、生成时间、驱动版本、Windows 版本。
- 截图：每个设置页面的截图（`NN_settings.png`）。
- 驱动版本信息：`pnputil /enum-drivers > drivers.txt`（管理员 PowerShell）。
- 注册表快照：`reg export "HKLM\SYSTEM\CurrentControlSet\Control\Print\Printers" printers.reg`。
- `C:\Windows\System32\spool\drivers\x64\3\` 下该驱动的所有文件清单（`dir /s > driverfiles.txt`）。
- 打印时的 **「打印处理器」** 名称：打印机属性 → 高级 → 打印处理器（应为 `eSSh6PPR` 或 `winprint`），截图。

---

## 5. `manifest.txt` 模板

```
# 编号  文件              内容/设置
01    01_blank_a4_600.prn        全白 A4 纵向 600x600 单面 1份
02    02_solid_a4_600.prn        全黑 A4 纵向 600x600 单面 1份
...
```

---

## 6. 回传方式

把这批文件（预计几十 MB）压缩后放到项目目录：

```
/path/to/e-STUDIO2323AM/eSTUDIO2323AM-captures/
```

用 U 盘 / 共享目录 / 网盘都行。**不要**做任何格式转换或十六进制编辑，保持原始字节。

## 7. 抓完之后（已完成）

抓包已经完成，放在 `eSTUDIO2323AM-captures/`，结论写在 `FINDINGS.md` 和
`docs/protocol-notes.md`：协议是 **PJL + JBIG-1**，不是原先假设的私有命令流。
协议已经用这 25 份样本做了逐字节回归（`make test-capture`）和抓包重放
（`make test-replay`），所以本文后续只作为"如果还要补抓（比如横向实机行为）"
的参考。

补抓时最有价值的是这几个样本：

1. 横向排版（确认 `ORIENTATION=LANDSCAPE` 时内容旋转方向）。
2. 空白页夹在多页作业中间，确认设备跳过空白页后的版面顺序。

本机（2323AM/2823AM）没有自动双面单元，所有抓包都是 `DUPLEX=OFF`，
所以双面样本不用再抓。

对每个新抓包，用 `./tools/prncheck <file.prn>` 检查：它会解出每页位图、
核对 `DOTCOUNT`，并用本项目编码器重编码后与原文件比对。
